# ARCHITECTURE.md — 인생네컷 (`lifefourcut`) 설계도

이 문서는 **인생네컷 웹 포토부스(`lifefourcut`)**가 어떤 구조와 부품들로 만들어지는지 비전공자도 한눈에 이해할 수 있도록 정리한 전체 설계도입니다.

---

## 1. 프로젝트 목표
- **서버 프로그램 없이 만들기**: 복잡한 별도 서버 프로그램이나 설치 도구 없이, 브라우저가 바로 읽을 수 있는 **정적 파일(내용이 고정된 기본 웹 파일인 HTML·CSS·JS)**만으로 포토부스를 만듭니다.
- **사진 보관만 클라우드 사용**: 사진 찍기, 프레임 합치기, 필터 입히기는 모두 사용자의 웹 브라우저 안에서 처리하고, 완성된 사진을 휴대폰으로 전달하기 위한 **사진 보관만 Supabase Storage(인터넷 파일 금고)**를 사용합니다 *(확장 C부터)*.

---

## 2. 3층 구조 표 (화면 층 / 기능 층 / 저장 층)

우리 프로그램은 역할을 깔끔하게 나누기 위해 **3층 구조**로 나누어 짓습니다.

| 층 이름 | 맡는 일 (쉬운 설명) | 담당 파일 | 사용 단계 |
| :--- | :--- | :--- | :--- |
| **1. 화면 층** | 사용자 눈에 보이는 화면 뼈대와 예쁜 디자인(버튼, 카운트 숫자, 휴대폰 세로 화면 모양)을 담당합니다. | `index.html`<br>`style.css` | 1단계 ~ 확장 C |
| **2. 기능 층** | 버튼을 눌렀을 때 카메라를 켜고, 5초를 세고, 사진을 찍어 합치고, 분위기 있는 색상 필터를 입히는 실제 동작을 담당합니다. | `js/app.js` (전체 진행 총괄)<br>`js/camera.js` (카메라·촬영)<br>`js/frame.js` *(확장 A부터)*<br>`js/filters.js` *(확장 B부터)* | 1단계 ~ 확장 C<br>1단계, 확장 A<br>*(확장 A부터)*<br>*(확장 B부터)* |
| **3. 저장 층** | 완성된 사진을 인터넷 파일 금고(Supabase Storage)에 올리고, 휴대폰으로 찍어 받을 수 있는 QR코드를 만듭니다. | `js/config.js` *(확장 C부터)*<br>`js/upload.js` *(확장 C부터)* | *(확장 C부터)* |

## 3. 화면 흐름 (사용자가 겪는 순서)

사용자가 앱을 켜서 사진을 찍고 받아 가기까지의 3단계 화면 흐름입니다.

1. **컷 수 고르기** *(확장 A부터 / 1단계에서는 기본 1컷)*
   - 화면에서 오늘 찍을 사진 장수(**1컷 / 2컷 / 4컷**)를 고릅니다.
2. **촬영 (버튼 → 5초 카운트 → 찰칵, 컷 수만큼 반복)**
   - **[촬영 시작] 버튼**을 누르면 화면에 **5초 카운트다운(`5 → 4 → 3 → 2 → 1`)**이 나타나고 **"찰칵"** 사진이 찍힙니다.
   - 1단계에서는 1번 찍고 끝나며, *(확장 A부터)*는 고른 컷 수(2컷 또는 4컷)만큼 이 과정을 자동으로 반복합니다.
3. **결과 (필터 고르기, QR로 받기)**
   - 찍힌 사진(또는 *(확장 A부터)* 세로로 합쳐진 인생네컷 프레임)을 화면에서 확인합니다.
   - 마음에 드는 **색상 필터를 고르고** *(확장 B부터)*, 완성된 사진을 **QR코드로 스캔해 휴대폰으로 내려받습니다** *(확장 C부터)*.

## 4. 부품 표 (파일별 핵심 함수와 역할)

각 자바스크립트(`js/`) 파일에 들어가는 핵심 부품(함수, 특정 일을 처리하는 명령 묶음) 목록입니다.

| 파일 | 함수 이름 | 넣는 것 (입력값) | 돌려받는 것 (결과값) | 하는 일 | 사용 단계 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `js/camera.js` | `startCamera(video)` | `video` (카메라 화면을 비출 HTML `<video>` 태그) | 카메라 연결 완료 신호 (`Promise`, 비동기 작업 완료 약속) | 기기의 카메라를 켜서 화면의 `video` 영역에 실시간 모습을 비춥니다. | 1단계 ~ |
| `js/camera.js` | `captureShot(video)` | `video` (현재 실시간 화면이 나오는 `<video>` 태그) | 찍힌 사진 1장이 그려진 `canvas` (브라우저 안의 투명 도화지) | 현재 카메라 화면의 한 장면을 순간 포착해 도화지(`canvas`) 한 장에 그대로 옮겨 찍습니다. | 1단계 ~ |
| `js/frame.js`<br>*(확장 A부터)* | `makeStrip(shots)`<br>*(확장 A부터)* | `shots` (찍은 사진 도화지 `canvas` 여러 장이 담긴 목록/배열) | 세로 프레임 한 장으로 합쳐진 완성 `canvas` (도화지) | 연속으로 찍은 2컷 또는 4컷 사진들을 위에서 아래로 차곡차곡 붙여 세로형 인생네컷 프레임을 만듭니다. | *(확장 A부터)* |
| `js/filters.js`<br>*(확장 B부터)* | `applyFilter(canvas, filterName)`<br>*(확장 B부터)* | `canvas` (원본 사진 도화지),<br>`filterName` (필터 이름 글자, 예: `'bw'`, `'warm'`) | 필터 효과가 입혀진 `canvas` (도화지) | 사진 도화지에 흑백, 따뜻한 느낌, 차가운 느낌 등 선택한 분위기 필터를 입힙니다. | *(확장 B부터)* |
| `js/upload.js`<br>*(확장 C부터)* | `uploadPhoto(canvas)`<br>*(확장 C부터)* | `canvas` (최종 완성된 인생네컷 도화지) | 업로드된 사진의 인터넷 주소 (`url` 문자열) | 완성된 도화지를 이미지 파일 데이터로 바꿔 Supabase Storage(인터넷 파일 금고)에 올리고 공개 주소를 받아옵니다. | *(확장 C부터)* |
| `js/upload.js`<br>*(확장 C부터)* | `drawQrCode(element, url)`<br>*(확장 C부터)* | `element` (QR코드를 그릴 화면 영역 태그),<br>`url` (사진의 인터넷 주소) | 없음 (화면의 `element` 안에 QR코드 그림 표시) | 받아온 사진 인터넷 주소(`url`)를 휴대폰 카메라로 바로 찍어 열 수 있는 네모난 QR코드로 그려 줍니다. | *(확장 C부터)* |
| `js/app.js` | *(전체 흐름 제어 함수들)* | 사용자의 버튼 클릭 동작 (촬영, 필터 선택, 다시 찍기 등) | 없음 (화면 전환 및 각 부품 실행) | 화면의 **버튼과 위 부품들을 순서대로 연결**하여 카운트다운부터 결과 확인까지 전체 순서를 지휘합니다. | 1단계 ~ 확장 C |

## 5. 데이터 흐름 (한 줄 요약)

카메라에 비친 내 모습이 최종 QR코드가 되기까지 데이터가 변해 가는 흐름입니다.

> **카메라 실시간 영상(`video`)** ➔ **1장씩 찍은 사진 도화지(`captureShot` → `shots`)** ➔ *(확장 A부터)* **세로 프레임 합치기(`makeStrip` → `canvas`)** ➔ *(확장 B부터)* **색상 필터 입히기(`applyFilter` → `canvas`)** ➔ *(확장 C부터)* **클라우드 업로드 후 인터넷 주소 발급(`uploadPhoto` → `url`)** ➔ *(확장 C부터)* **화면 속 QR코드 완성(`drawQrCode`)**

## 6. 꼭 지켜야 할 기술 결정 3가지

1. **카메라는 보안 컨텍스트(`HTTPS` 또는 `localhost`)에서만 사용**
   - 웹 브라우저는 개인정보 보호를 위해 아무 곳에서나 카메라를 켜주지 않습니다.
   - 반드시 안전한 연결 환경(**보안 컨텍스트**, 주소창이 `https://`로 시작하거나 내 컴퓨터의 연습용 서버 주소인 `http://localhost` / `http://127.0.0.1`)에서 실행해야 카메라가 정상으로 켜집니다.
2. **일반 `<script>` 태그를 정해진 순서대로 불러오기**
   - `<script type="module">`은 사용하지 않으므로, `index.html` 맨 아래에서 **부품 파일들을 먼저 불러오고 총괄 파일(`js/app.js`)을 맨 마지막에 불러와야** 오류가 나지 않습니다.
   - **전체 단계 불러오는 순서**:
     1. 외부 CDN 라이브러리 *(확장 C부터: Supabase, QRCode 도구)*
     2. `js/config.js` *(확장 C부터)*
     3. `js/camera.js` (1단계부터)
     4. `js/frame.js` *(확장 A부터)*
     5. `js/filters.js` *(확장 B부터)*
     6. `js/upload.js` *(확장 C부터)*
     7. `js/app.js` (1단계부터 — 항상 맨 마지막에 연결)
3. **사진 보관 정책을 사용자가 확인할 수 있게 화면에 명시**
   - *(확장 C부터)* QR코드 생성을 위해 사진이 클라우드(Supabase Storage)에 올라갈 때, 사용자의 사생활 보호와 안심을 위해 **"업로드된 사진은 QR코드 다운로드 용도로만 쓰이며 일정 기간 후 삭제됩니다(또는 공개 링크로 저장됩니다)"** 같은 **사진 보관 안내 문구**를 결과 화면에 눈에 잘 띄게 표시합니다.
   - 또한 `js/config.js`에는 관리자용 비밀 키(`sb_secret_...`)를 절대 넣지 않고 브라우저 공개용 키(`anon` / `sb_publishable_`)만 사용합니다.

## 7. 1단계 (기본 촬영) 세부 설계 명세 (`step1-basic-shot.md` 기준)

1단계 기본 촬영을 구현할 때 화면(`ui`) 에이전트와 기능(`logic`) 에이전트가 맞춰야 할 세부 설계입니다.

### 7-1. 1단계에서 새로 만드는 파일 (총 4개)
| 파일 경로 | 담당 에이전트 | 역할 요약 |
| :--- | :--- | :--- |
| `index.html` | 화면 (`ui`) | 카메라 미리보기(`<video>`), 5초 카운트다운 숫자, 촬영·다시 찍기 버튼, 결과 표시 영역 구조 작성 |
| `style.css` | 화면 (`ui`) | 휴대폰 세로 화면 맞춤 스타일 및 화면 숨김용 `.hidden`(`display: none;`) 클래스 정의 |
| `js/camera.js` | 기능 (`logic`) | 카메라 연결(`startCamera`)과 사진 1장 캡처(`captureShot`) 부품 함수 제공 |
| `js/app.js` | 기능 (`logic`) | 페이지 시작 시 카메라 켜기, [촬영하기] 클릭 시 5초 카운트다운 후 촬영·결과 표시, [다시 찍기] 연결 |

### 7-2. 1단계 사용 함수 이름과 넣는 것 / 돌려받는 것
*(규칙에 따라 기존 함수 이름을 절대 바꾸지 않고 그대로 사용합니다.)*

| 파일 | 함수 이름 | 넣는 것 (입력값) | 돌려받는 것 (결과값) | 하는 일 |
| :--- | :--- | :--- | :--- | :--- |
| `js/camera.js` | `startCamera(video)` | `video` (카메라 영상을 보여줄 `<video>` 요소) | `Promise` (카메라 연결 성공/실패 약속 객체) | 기기 카메라 권한을 요청해 `video` 태그에 실시간 화면을 연결합니다. |
| `js/camera.js` | `captureShot(video)` | `video` (현재 영상이 재생 중인 `<video>` 요소) | `canvas` (찍힌 사진 1장이 그려진 새 도화지 요소) | `video`의 현재 화면 크기에 맞춰 새 `canvas`를 만들고 그 순간의 장면을 그려 돌려줍니다. |

### 7-3. 1단계 `index.html`의 `<script>` 불러오는 순서
1단계에서는 아직 쓰지 않는 확장 A·B·C 파일은 빼고, 아래 **2개 파일만 순서대로** `</body>` 바로 위에서 불러옵니다.

```html
<!-- 1. 카메라 부품 먼저 불러오기 -->
<script src="js/camera.js"></script>
<!-- 2. 전체 화면 흐름과 버튼을 연결하는 총괄 파일 마지막에 불러오기 -->
<script src="js/app.js"></script>
```
